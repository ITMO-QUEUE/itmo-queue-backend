# Контракты API

OpenAPI генерируется FastAPI из маршрутов и Pydantic-схем:

- `/docs` — Swagger UI с возможностью выполнить запрос;
- `/redoc` — ReDoc;
- `/openapi.json` — источник контрактов для frontend и будущей генерации TypeScript.

Сейчас реализован только `GET /health`: без параметров и тела запроса,
ответ `200` — `{"status":"ok"}`. Специальных ошибок у этого метода нет;
доступность PostgreSQL и Redis он не проверяет.

## При добавлении каждого метода

1. Подключите роутер модуля к общему `/api/v1`.
2. Задайте `tags`, `summary`, `description` и уникальный стабильный `operation_id`.
   Например, для будущего CRUD групп: `createGroup`, `listGroups`, `getGroup`,
   `updateGroup`, `deleteGroup`. Изменение operation ID влияет на генерируемый клиент.
3. Опишите тело запроса отдельной Pydantic-моделью. Задайте типы, обязательность,
   ограничения и примеры через `Field`. Разделяйте схемы создания, изменения и ответа.
4. Укажите `response_model`, успешный `status_code` и `response_description`.
   Для `204` не возвращайте JSON-тело и не задавайте модель ответа.
5. Описывайте path/query-параметры через `Path`/`Query`: назначение, границы,
   значения по умолчанию и примеры. Для списка явно определяйте пагинацию.
6. В `responses` перечислите реальные ошибки метода и их Pydantic-схемы.
   Описание ошибки не реализует её обработку: фактический код и тело должны совпадать.

## Ошибки

Пока используем стандартные ответы FastAPI без глобальной замены обработчиков:

| Код | Когда применяется | Тело |
| --- | --- | --- |
| `422` | Валидация тела или параметров | Стандартный `HTTPValidationError`, добавляется FastAPI автоматически |
| `404` | Сущность не найдена | `{"detail":"..."}` через `HTTPException` |
| `409` | Конфликт уникальности или согласованное ограничение операции | `{"detail":"..."}` через `HTTPException` |

Коды `404` и `409` добавляйте только в методы, которые действительно их возвращают.
Пример объявления ошибки будущего метода (это не готовый endpoint):

```python
from fastapi import HTTPException
from pydantic import BaseModel, Field


class ErrorResponse(BaseModel):
    detail: str = Field(description="Причина ошибки", examples=["Group not found"])


# В декораторе метода:
# responses={404: {"model": ErrorResponse, "description": "Группа не найдена"}}
# В обработчике при отсутствии сущности:
# raise HTTPException(status_code=404, detail="Group not found")
```

Не описывайте авторизацию, несуществующие методы и ошибки, которые ещё не реализованы.
Не включайте внутренние исключения SQL или секреты в ответы и примеры.

## Проверка перед PR

- Откройте `/docs`: проверьте параметры, схемы, примеры и успешные/ошибочные ответы.
- В API-тестах проверьте реальные статусы и тела ответов, включая ошибки.
- Проверьте `/openapi.json`: уникальность operation ID, ссылки на модели,
  обязательные поля, ограничения и ответы должны соответствовать реализации.
- Изменение обязательности, типов, кодов и структуры ответа согласуйте с frontend.

Генерация TypeScript-типов будет отдельной задачей. Спецификацию вручную не дублируем.

## Студенты (Students CRUD)

Все методы управления студентами доступны только администратору. 
В запросах к этим эндпоинтам **обязательно** должен передаваться заголовок авторизации:
`x-admin-token: super_secret_admin_token`

### Именование методов (operationId)
Для удобной генерации TypeScript-клиентов все методы именуются в стиле `camelCase`:
| HTTP Метод | URL | operationId | Описание |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/v1/students` | `createStudent` | Создать нового студента |
| `GET` | `/api/v1/students` | `listStudents` | Получить список студентов (с пагинацией и поиском) |
| `GET` | `/api/v1/students/{id}` | `getStudent` | Получить данные конкретного студента |
| `PATCH` | `/api/v1/students/{id}` | `updateStudent` | Обновить данные студента |
| `DELETE` | `/api/v1/students/{id}` | `deleteStudent` | Отключить аккаунт студента (Soft Delete) |

### Особенности работы с данными
*   **Пароли:** При создании и обновлении студента клиент передает пароль в открытом виде (поле `password`). Сервер хеширует его через `bcrypt`. **В ответах API пароль и его хеш никогда не возвращаются.**
*   **Пагинация и поиск:** В методе `listStudents` доступны query-параметры:
    *   `limit` (по умолчанию 20, максимум 100) — количество записей.
    *   `offset` (по умолчанию 0) — смещение.
    *   `search` — поиск по имени, логину или номеру ИСУ (частичное совпадение).
*   **Мягкое удаление:** При вызове `DELETE` студент не удаляется из базы физически, а его флаг `is_active` становится `false`. Это нужно для сохранения истории защит. Если запросить `getStudent` для отключенного аккаунта, вернется ошибка `404`.

### Структура ошибок

#### 422 Unprocessable Entity (Ошибка валидации)
Возвращается FastAPI автоматически, если переданы неверные типы данных, пустые обязательные поля или пароль короче 6 символов.
```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["body", "password"],
      "msg": "String should have at least 6 characters",
      "input": "123"
    }
  ]
}
```

#### 403 Forbidden (Нет прав)
Возвращается, если запрос отправлен без заголовка `x-admin-token` или токен неверный.
```json
{
  "detail": "Access denied. Admin rights required."
}
```

#### 409 Conflict (Дубликат данных)
Возвращается при попытке создать или обновить студента, если указанный `login` или `isu` уже заняты другим студентом.
```json
{
  "detail": "Login or ISU already exists"
}
```

#### 404 Not Found (Не найдено)
Возвращается, если студент с указанным `id` не существует, либо его аккаунт был отключен (soft delete).
```json
{
  "detail": "Student not found"
}
```
