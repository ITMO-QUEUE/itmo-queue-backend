# Проверка пользовательских сценариев ITMO.Queue

Анализ выполнен по backend-коду ветки `main` и существующим тестам. Основные операции живой очереди реализованы: авторизация, создание сеанса, запись студентов, вызов и проведение защиты, управление очередью и просмотр истории.

| Область | Состояние |
|---|---|
| **Авторизация** | Реализованы собственные учётные записи, роли и сессии в Redis. |
| **Создание сеанса** | Преподаватель задаёт дисциплину, работы, приоритеты, квоту и состав принимающих. |
| **Запись студента** | Можно выбрать несколько разрешённых работ и приложить ссылку к каждой. Проверяются доступ к очереди, запрет и повторная запись. Квота допускает резерв. |
| **Живая очередь** | Реализованы позиции, топ-3, отмена, перенос, обмен местами и продвижение из резерва. Обновления передаются через SSE и WebSocket. |
| **Защита** | Реализованы ручной запуск сеанса, параллельная работа преподавателей, вызов по очереди и вне её, начало защиты, результаты и обработка неявки. |
| **История** | Сохраняются попытки, результаты отдельных работ и персональные уведомления. |
| **Настройки** | Назначенные преподаватели могут управлять сеансом, записью и его параметрами. |

## Расхождения и ограничения

- При создании сеанса место необязательно, а запись по умолчанию открыта. В `main` используется прежний контракт создания с `location`, `stream_ids` и существующими `work_id`.
- Доступ студента проверяется по потоку; отдельной проверки допуска именно к дисциплине в обработчике записи нет.
- Студент может самостоятельно перенести запись в конец только один раз, хотя сценарий такого ограничения не содержит.
- Повторная отмена через `/entries/me` может вернуть `404`. Безопасный повтор после потери ответа предусмотрен не для всех действий.
- Для обновления прогноза ожидания клиенту нужно повторно запросить состояние очереди. Предупреждения, подтверждения и отображение потери связи зависят от клиентского приложения.

## Проверка

Прошли 12 тестов, не требующих работающей базы. Интеграционный тест жизненного цикла не удалось выполнить: PostgreSQL отклонил подключение. Корректность полного сценария с базой, Redis и интерфейсом остаётся неподтверждённой.
